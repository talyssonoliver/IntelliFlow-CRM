    Issue    : If createLogger throws, nothing is cached, so apiLog builds the logger again on every request; in development each attempt starts a pino-pretty worker thread before pino rejects the level, and those threads are never released.
    Evidence : getApiLogger does `apiLogger ??= createLogger({...})`. When createLogger throws, apiLogger stays undefined and the catch in apiLog only sets `failureReported`, so the next apiLog call runs createLogger again. Nothing references or closes that transport, so every tRPC request (up to 2 calls per request on the slow path) leaks one more worker thread.
