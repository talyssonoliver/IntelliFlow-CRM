  [HIGH] apps/api/src/modules/calendar/booking-abuse.ts:74-79 — failed-attempts-disable-public-booking
    Issue    : Failed booking attempts consume the shared event-type quota, allowing anonymous visitors to disable an event's bookings for an hour without booking anything.
    Evidence : The event-wide count queries `bookingAttempt` by `eventTypeId`, and `byEventType >= BOOKING_CAPS.perEventTypePerHour` rejects everyone. public-booking.router.ts commits each attempt before validating the requested slot.     Fix      : Keep email/IP quotas attempt-based, but count successfully created public appointments for the shared event-type quota and enforce it inside the booking transaction under the booking lock.

  [MEDIUM] apps/api/src/modules/calendar/booking-email.ts:108-118 — unverified-recipient-content-injection
    Issue    : Anonymous visitors can send attacker-authored messages to arbitrary email addresses through the booking confirmation's name field.
    Evidence : `Hello ${d.bookerName}` is included in both confirmation bodies, while `to: [d.bookerEmail]` uses an unverified address.
